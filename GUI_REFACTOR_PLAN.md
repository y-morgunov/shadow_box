# План рефакторинга desktop GUI

Цель: отделить данные настроек и подготовку запуска от Qt-виджетов, не менять интерфейс и работу генератора. Сейчас диапазоны параметров, проверка JSON и построение CLI находятся внутри большого класса Window; их трудно проверять без графической сессии.

1. Вынести описания числовых параметров, проверку формата настроек v1 и построение аргументов генератора в `gui_settings.py`, без зависимости от Qt. Сохранить диапазоны, значения по умолчанию, имена CLI и совместимость старых пресетов без X/Y.
2. Подключить эти функции в `gui.py`; оставить управление QProcess, отмену, отображение и файловые диалоги в Window. Не менять геометрию, формат JSON, внешний вид и пути результатов.
3. Добавить проверки границ/нечисловых значений, старого формата без смещения и точной передачи смещения/путей с пробелами в CLI. Существующие GUI-тесты проверят сохранение настроек, генерацию, OpenGL, экспорт и сохранение предыдущего результата после отмены.
4. Запустить тесты чистых функций и интеграционные GUI-тесты с изолированным QSettings. Документировать разделение модулей.

Отдельный контроллер процессов и полная перестройка виджетов пока не нужны: это расширило бы рефакторинг без изменения пользовательских возможностей. Веб-версия использует существующий генератор самостоятельно.

## Результат

Пункты 1–4 выполнены. Формат JSON сохранён; целочисленные параметры, записанные в JSON как `80.0`, нормализуются перед передачей argparse. Четыре проверки чистых функций и две GUI-интеграции прошли (`DISPLAY=:0 SHADOW_GUI_TEST=1 .venv/bin/python -m unittest test_gui -v`, 6 tests, exit 0). В тестах исправлен жизненный цикл QApplication и GL-окон: окна удаляются через DeferredDelete до завершения Qt; пользовательские процессы приложения не затрагиваются. `py_compile` и `git diff --check` прошли.
